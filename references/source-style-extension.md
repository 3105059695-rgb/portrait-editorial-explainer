# 从自由组合到部件扩展

> 该页说明早期组合机制或自由UI。新版全部机制从[完整效果库](full-effects-guide.md)选择；视觉基准是[最初完整原片](approved-editing-direction.md)，不由某个后做样例定义。

新题材先重新设计信息结构，再复用绘制与运动能力。改变布局、交互链、焦点和素材，是常规用法，不需要证明旧六套完整场景都失败后才能开始。

## 先判断需要哪一层变化

| 需求 | 实现方式 |
|---|---|
| 新布局、新主题、新界面状态 | 在 `ui-stage` 的 `nodes/tracks/camera` 中设计；通常不改代码 |
| 刚好需要现成的完整动作链 | 复用效果索引中的对应场景，并使用本期素材和实测时点 |
| 现有节点不能表达的形状、交互或遮挡 | 扩展通用节点或新增独立效果，同时更新契约 |

例如“比较两组结果”可组合两列内容区、选中态和结果反馈；不必因为库存组件有上传云就将比较讲成上传。也不要仅为每期换布局重复实现整个渲染器。

## 扩展最小交付

1. 写清本期对象、动作、可见结果，以及现有能力缺少的部分。例如“同一物体穿过容器的前后边缘”需要明确遮挡，不能仅改标题。
2. 新通用节点加入 UI 类型、绘制逻辑和字段验证；新完整效果在工程 `src/effects/` 接收 `EffectProps` 并输出 SVG 组，注册到类型、渲染器和校验器。字段细节、默认值及一份可运行 JSON 同步交付。
3. 使用 `motion.ts` 的确定性函数，所有变化由帧时间决定。对象 ID、关键帧、素材槽和遮挡层次明确；不用 `Math.random`、`Date.now` 或独立 CSS 时钟驱动导出。
4. 保持 544 逻辑宽与适配后的高度，图像和人物不变形。复用 [UI 设计系统](ui-style-system.md) 的层级、材料与阅读规则，而不是固定复制原片构图。
5. 渲染实际需要比例的局部样段，检查前、中、后及连续播放；对承诺兼容的其他比例再做相应检查。换一组不同内容验证部件是否仍有意义，不只测试替换标题。
6. 技术结果记为已实现或已验证，风格认可单独记录真实用户反馈及对应样段。某个部件获认可不代表全库或之后每期自动获认可。

所有素材从相对 `public` 路径读取。需要工具、浏览器或账号时运行时检测，不写入作者路径。示意 UI 标明示意；图片缺失时可用有含义的中性图形，不能用无关 emoji 填空。需要透视或 3D 时实际处理透视和前后遮挡，避免将普通缩放称作 3D。

可复用且已经验证的部件可以纳入公共模板。本期私有配音、账号截图和版权参考保留在本期工程，公共 Skill 提供机制和使用方法。
