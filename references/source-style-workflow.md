# 从已有声音到本期 UI 开头

> 适用范围：这是辅助 UI/机制资料，不能替代 [已确认的数字人口播剪辑方向](approved-editing-direction.md)。RC2 界面演示不再作为目标风格基准；新一期从真实口播与镜头分镜进入制作。

## 素材分流

| 输入 | 下一步 | 可用时钟 |
|---|---|---|
| 真人未经剪辑口播 | 在已授权的 ChatCut 工程里粗剪口误、废片、无效重复与冗余停顿；保留自然呼吸、因果和原速 | 实际导出的剪后母带 |
| 已完成粗剪的口播 | 检查连续性与字幕，沿用；不再次自动删句 | 现有成片时间 |
| 数字人口播视频 | 默认跳过语音粗剪，确认已定稿 | 数字人音画共同时间 |
| 最终配音音频 | 直接分句并定动作，默认不新增人物 | 配音时间 |

ChatCut 操作见 [衔接指南](chatcut-handoff.md) 和 [口播流程](presenter-workflow.md)。先确认工具可用，再使用当前导入、转录、剪辑和导出能力；文档不存作者账号 ID、资产 ID 或私人路径。工具不可用时如实报告，不能静默换后端并声称完成 ChatCut 粗剪。

保留实际操作产生的映射 JSON，例如多个 `{sourceStart,sourceEnd,outputStart,outputEnd,speed:1}`。画面和声音使用同一映射。独立母带存在时人物视频静音，避免双人声。现有验证器检查映射文件存在，不证明剪切内容正确。

## 开头先行

1. 读取最终母带前 15 秒和首句语境。从第 0 秒做本期开头，不任取最花哨的中段。
2. 按 [UI 设计系统](ui-style-system.md) 写本段信息、界面结构、具体内容、状态链与镜头焦点。先决定需要浏览、对照、编辑还是观察结果，再布置 UI；题材变化允许完全改变布局和剪法。
3. 选择 10–15 秒内的完整句末作为 `sample.duration`。提取实测字幕与关键词时点，将主要状态变化连接到关键词；不要为了既有动画长度删掉半句话。
4. 优先用 `ui-stage` 组合节点和状态轨迹，或在语义完全适合时复用完整场景。界面设计与程序字段分别参考 [设计系统](ui-style-system.md) 和 [组合契约](ui-composition-contract.md)。
5. 运行 production 校验、编译和 opening 渲染。以手机阅读尺度连续看听，检查内容是否足够、操作是否可辨、字幕是否同步、人物是否挡住当前焦点。
6. 交付 `opening.mp4`，获取用户对“这类 UI 感觉是否接近、内容是否讲清”的反馈。此时样段必须可观看，不以分镜文档代替成片；风格未认可前不扩展全片。
7. 据具体差异修改开头；认可后记录真实 `review` 并继续。JSON SHA 改变时旧审核文件失效，按当前稿重新核对。

## 反馈如何转成修改

| 用户感受 | 优先检查 | 有效调整 |
|---|---|---|
| UI 感太少 | 是否只有标题、图片和空卡片；是否缺少上下文、控制与反馈 | 补足有内容的界面结构与可见状态，而非添加装饰按钮 |
| 像 PPT | 是否每句话都淡出、重置画布；内容是否只有说明文字 | 在同一空间让对象连续变化，动作后保留结果 |
| 太像固定模板 | 是否反复套用同一布局、搜索或上传链 | 按本期信息关系重新设计结构，保留部件和视觉规则 |
| 太乱、看不懂 | 焦点是否过多、所有层级同时运动、结果无停留 | 保留上下文，只突出当前动作；给关键状态阅读时间 |
| 整体不像参考类型 | 字体层级、界面占比、内容密度和相机是否偏离 | 对照相关连续片段逐项调整，不要求剪辑顺序一致 |

## 新内容与组件选择

通常先通过 `ui-stage` 重新组合界面、素材与状态，不必修改 TSX。旧六场景适合时可以直接复用，但不能要求新内容都能套入其中。现有节点或运动能力确实不能表达时，按 [扩展约定](source-style-extension.md) 新增可复用部件或效果。
