# 从已有声音到本期开头

## 素材分流

| 输入 | 下一步 | 可用时钟 |
|---|---|---|
| 真人未经剪辑口播 | 在已授权的ChatCut工程里粗剪口误、废片、无效重复与冗余停顿；保留自然呼吸、因果和原速 | 实际导出的剪后母带 |
| 已完成粗剪的口播 | 检查连续性与字幕，沿用；不再次自动删句 | 现有成片时间 |
| 数字人口播视频 | 默认跳过语音粗剪，确认已定稿 | 数字人音画共同时间 |
| 最终配音音频 | 直接分句并定动作；默认不新增人物 | 配音时间 |

ChatCut操作细节在 [现有衔接指南](chatcut-handoff.md) 和 [口播流程](presenter-workflow.md)。先确认真实工具连接，再使用插件的当前导入/转录/剪辑/导出能力；文档不得存作者账号ID、资产ID或私人路径。工具不可用时不能假称做过粗剪，也不能静默换后端并冒充ChatCut。

保留剪切映射JSON，例如多个 `{sourceStart,sourceEnd,outputStart,outputEnd,speed:1}`。画面和原声使用同一映射。独立母带存在时人物视频静音，避免双人声。记录的映射须来自真实操作；现有验证器只检查文件存在，不证明映射内容正确。

## 开头先行

1. 确认本期最终音轨，读取前15秒及首句语境，不任取全片最花哨的段落。
2. 把这段口播写成2–4个动作关系，既有参考气质，也能讲清本期话意。不是六组件大串烧。
3. 选择10–15秒内完整句末作为sample.duration，补字幕和关键词marks。
4. 运行production校验与编译、渲染opening，完整看听一次，修掉遮挡、断句和错位。
5. 将opening.mp4交给用户，问这段是否达到其“人眼觉得差不多”的标准。这里停在可审阅成品，不先渲染全片。
6. 用户反馈“不像”时回看相关原片时段，明确差异并只迭代开头。用户认可后才记录review并扩展全片。最终稿变动导致JSON SHA变化时，旧review失效。

## 新内容无法用现有组件表达

先尝试同一组件内换素材/顺序/时长/动作焦点，再组合合适机制。仍表达不了，新增镜头而不是给台词强配无关动画。扩展依照 [约定](source-style-extension.md)，每个新效果都要可复用、有局部样段，保留状态连续与同一音频时钟。

## 交付记录

保留输入类型、实际粗剪状态、母带文件、字幕来源及精度、素材权属来源、关键动作表、实际跑过的检查、已看过时段和用户反馈。机器checks和人眼风格结论分开。原片对照仅用于本地分析，分享Skill时不自动附带原作者画面/音频/肖像。
