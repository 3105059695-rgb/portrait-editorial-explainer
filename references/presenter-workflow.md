# 持续制作竖屏口播

## 本期输入与主时钟

先区分素材用途：本期人物/数字人口播、只有声音的旁白、风格参考、可用B-roll。检查文件的真实时长、比例、音轨以及是否已含字幕。沿用同系列已明确的语言和声音选择，只有确实缺少关键输入时简短询问。

- 真人原始口播：先用 ChatCut 粗剪，以剪后人声为主时钟；转写并校对人名、术语、数字，画面与声音保持相同剪切映射。
- 数字人口播：默认不做粗剪，沿用定稿视频/声音的时间轴；仍检查口型同步、时长和字幕。只有用户要求删改，或发现需修复的明确缺陷时，才处理对应片段。
- 已粗剪素材：先检查现有版本并沿用，不重复执行口癖/停顿清理。无法确定是否数字人且会影响剪法时，只问一个简短问题，不凭人物外观判断。
- 只有旁白：按声音设计画面。只有明确要求数字人且缺少人物时，才确定可用头像/服务路径，不把别期人物当作默认资产。
- 只有稿件：先确认必要事实、设计语义动作，再以最终录音校准。预估时间不能称作实测同步。
- 配音、BGM、原视频音轨避免重复播放。已有主声音时将人物视频静音，使用一份声音母带；声音修改服从当前用户要求。

## 真人素材先用 ChatCut 粗剪

这是用户于2026-10-12明确补充的默认流程：**真人原始素材 → ChatCut 粗剪 → 固定剪后口播时间轴 → V3 动效、素材、字幕与声音设计**；数字人直接进入定稿时间轴之后的步骤。

1. 优先使用用户给定的 ChatCut 工程与其中已有素材；收到本地视频时，按当前 `chatcut:asset-import` 导入，若环境提供 ChatCut 插件，执行前读取其 `chatcut:chatcut-plugin-basics` 与 `chatcut:talking-head-guide` 对应工作流；工具接口以当前环境为准。没有这些说明时先查本包 [ChatCut 衔接指南](chatcut-handoff.md)，确认工具可用，不凭名字猜参数。素材已有转写时直接复用并校对，不重复导入。通过现有授权完成必要的可逆粗剪，不重复询问是否要粗剪。
2. 从文字稿和实际听看决定保留内容：去掉明确的口误、重复试录、无意义口癖、开关录制废片和过长空等；保留完整意思、连接词、强调、自然呼吸与必要停顿。不能只靠静音阈值整批剪到无缝，也不把不同失败试录的残句拼成新观点。默认不擅自改稿、重排论证或为了时长删除有效信息。
3. 在 ChatCut 时间轴中同步剪画面与原声，保持保留片段的原始速度；调整完结构后处理切口音频衔接。回读实际时间轴、抽听所有修改切口，检查吞字、爆音、口型、黑帧、手势跳切和语义连续性。不能仅修改文字稿或列出剪辑建议就声称已经粗剪。
4. 保留原始媒体和可编辑工程，记录源素材、源入/出点、剪后入/出点及删减原因，可用 `roughcut-edl.json` 或等价清单，格式示意见 [剪辑映射示例](../examples/roughcut-map.json)。将真正可用的剪后画面与匹配人声交给动效阶段；可以导出中间片，也可以让 Remotion 按同一剪辑映射读取原媒体，不能假定两个软件会自动共享时间轴。ChatCut 不可用或交接未成功时明确说明，不能把未经处理的原片标为粗剪完成。
5. 固定粗剪后，再生成/重映射字幕、关键词事件、B-roll、音乐和音效时点，以剪后总时长设置 Root。后续若再删一句或改停顿，必须更新受影响的所有时间点与映射，重新检查同步。不得用原片字幕时间直接套剪后视频。

“保留原人声”指保留说话者的声音、表达和保留片段原速，不表示真人原片不能做上述粗剪。数字人跳过的是这一步语音清理，不是跳过素材、字幕或音画检查。

## 换题时重新导演

先把重点句写成四列：**说了什么 → 用什么真实资料或物体 → 它发生什么变化 → 镜头关注哪里**。使用 [V2 分镜契约](storyboard-contract.md) 的稳定 cueId/objectId；按 [导演手册](director-playbook.md) 输出本期 JSON。文字准确性与视觉因果比贴纸数量更重要。

例如“用AI整理客户问题”可以做：原聊天里的问题被选中→问题移动进入整理窗口→同一批条目归组→镜头推近新分组。不要把本案例的“钱币→公司→公文包”换上客户标签，就当作已经换题。

镜头类型按内容选择：

| 当前需要 | 优先选择 |
| --- | --- |
| 引入人物判断、关系或反常识问题 | 人物主画面＋一件主题物体；保留脸和手势 |
| 描述具体物件/区别 | 特写→横移关注另一物件→回拉建立关系 |
| 提供证据或展示操作 | 真实资料/可读UI占据舞台，必要时整体曲面化；镜头跟随选中与结果 |
| 解释抽象概念或关系 | 漫画道具经历具体动作，因果产生结果 |
| 跨越章节或画面语境 | 物体边缘、窗口、圆窗带出下一场，旧场和新场短暂共存 |

不要按每句台词强制换背景，也不为凑效果塞入与主题无关的软件窗口。大镜头运动后保留阅读时间；长口播穿插人物回场与较稳定的解释段，避免十秒样例的密度整片重复。

## 人物、字幕与构图

逻辑画布540×960可作为9:16设计基准。人物开场通常更大；进入B-roll时可用半身小窗持续保留或在合适段落回场。位置应跟随当前证据区避让：脸、手势、关键数值、状态按钮和字幕不能相互遮挡。

字幕通常保持屏幕坐标，不参与场景的推近、鱼眼或旋转。V3字幕y867及字号23是试剪参数，不是平台保证；新项目重新检查底部交互区域、长句换行和最小可读字。深浅场交接时检查中间帧，必要时添加简洁底板。不要只在场景终态切换字幕颜色。

人物来源25fps而图形50fps时，保留人物真实节奏，不虚称增加了拍摄帧。图形用确定性的帧驱动，避免时间依赖和随机漂移破坏离线渲染。

## 长度与连续集数

从本期最终音频长度（真人为粗剪后，数字人为定稿人声）设置 episode.json 的 duration/fps，默认引擎自动计算总帧数；按自然段编排 scenes 和 beats，不能按旧10.74秒截断或把整套动作匀速拉长。每期保留字幕、事件表、素材来源和实际命令，避免下期从旧素材路径盲猜。

复用视觉系统而非主题道具：配色、字体、线宽、相机曲线、窗口接力机制可以复用；开场事件、主题证据、物体身份与动作落点应重设。用户只改字幕同步时，保留已经认可的设计。

## 对照与交付

用户要求贴近参考时：看原参考的目标段落前/中/后状态，对照景别、主体占比、颜色、因果动作和速度变化；写短差异表后动手。若原片不可用，说明当前基于已认可V3或联系表，不声称重新看过原片。

完成实际视频和可编辑项目。至少检查编码/解码、字幕边界、开头、关键词、转场中间态、结尾和音频混合；抽听实际声音，未完整听看如实记录。包内示例能渲染、成片技术通过、画面抽查、用户风格认可、平台审核是不同结论。
