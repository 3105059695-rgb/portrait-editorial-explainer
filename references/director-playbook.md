# 给模型的分镜导演方法

目的：把不同口播转换为可执行分镜，模型负责理解内容与选择动作，代码负责构图、物体、相机、材质和动画。不要让能力较弱的模型从零编写一整段 React 动画，也不要把旧案例逐字换标签。

## 先做四件事

1. **确定最终声音。** 真人原始素材先在 ChatCut 粗剪，数字人沿用定稿。只有稿件时允许做草案，但 `timing` 必须是 `estimated` 或 `demo`，不编造实测时间。
2. **逐句理解。** 为每个字幕 cue 写出“主体、动词、关系、证据”。分清讲的是一个对象、两个对象的区别、对象的移动/整理、数字结果，还是人物态度。
3. **决定观众要看见的变化。** 用一句话写清前后状态。例如“混杂的客户提问移动进同一收件箱，然后按主题归组”。“让画面更酷”“弹入三个关键词”不是状态变化。
4. **选择合适的机制与本期素材。** 按下表选，而不是固定四幕。若一个机制不能准确表达，拆成两镜，或补真实素材，必要时扩展组件；不能为了迁就组件改变原话。

## 动作选择表

| 讲述关系 | mechanism | objects 怎么定义 | beats 怎么写 | 不该这样用 |
| --- | --- | --- | --- | --- |
| 介绍一个实物、概念或关键细节 | `object-focus` | 被讲到的对象；有真实外观时挂 `assetId` | `reveal` 建立对象，关键词处 `focus`，需要时 `result` | 每句话都推近一个文字方框 |
| 两者区别、前后状态、条件比较 | `compare-pan` | 两个或更多具有共同参照的对象 | 至少两个 `focus/select`，分别落在实际提到的对象；结束回到关系 | 两份数值来自不同口径却画成同一尺度 |
| 送入、带到、提交、离开、进入、交付 | `route-transfer` | 移动物、起点、终点至少三个对象 | `transfer` 的 targetId 是移动物，withId 是终点；先关注起点，抵达再反馈 | 只改变箭头和标题，移动物没有动 |
| 收集、分类、合并、归档、整理 | `group-sort` | 至少两个条目与一个容器 | `group` 的 targetId 是条目，withId 是容器；多条目可逐个落位 | 把“删掉”误画成“归档”，或把条目凭空变多 |
| 展示出处、查看报告、操作结果 | `evidence-zoom` | 证据里的焦点或对应资料对象 | `select/focus/result` 按语义强调；真实资料用 evidenceAssetId | 缺证据时把示意UI称作真实网站截图 |
| 计数、占比、累计、差额 | `metric-build` | 明确的统计对象 | `count` 与真实数字同拍；metric只填稿件支持的数据 | 为了好看发明百分比、进度或精度 |
| 解释原因、关联线索、把信息串起来 | `question-thread` | 有明确联系的两个或更多对象 | `connect` 指定 targetId→withId，线随关键词连通 | 随便画关系线暗示不存在的因果 |
| 强调人物判断、情绪、自然停顿 | `presenter` | 可不创建对象 | 人物与声音保持连续，可以不添加beats | 整片都留在人物页，或在需要读材料时让人物遮挡 |

动作字典是可组合的基础，不限定选题。产品对比、教学、历史解释、生活技巧、科技讲解都应先找句子的关系。不要先套“开头→钱币→公司→采访→问号”的路线。

## 物体与素材

`document/message/folder/device/product/person/coin/chart/image/symbol` 是基础绘制形式。`label` 告诉观众是什么，`detail` 补必要上下文；它们不能替代真正动作。

实际产品、景点、人物、品牌、界面优先用本期合法可用的图片/SVG，通过 `assets[].id` 和 `objects[].assetId` 接入。素材保持局部相对路径，source记录出处。`image`不表示任意视频都能直接放入图像组件，先看引擎支持范围。

同一对象在后续镜头保留相同id与素材；镜头可以改变大小、位置和观察方式。出现新版本/新身份时再建新id。不要复制六个相同物体只为了填满屏幕。

如果要讲地图路线、精确科学图或复杂3D，而基础机制表达不清，应先制作对应的真实图示/媒体或扩展新的渲染组件。不要声称八个机制已覆盖所有创意。

## 从句子到可编译 JSON

依据 [分镜契约](storyboard-contract.md) 创建一个 JSON 文件。按以下顺序填，避免来回发散：

1. 原样放入已校对 `captions`，保留真实时间；设本期时长、来源、粗剪状态、媒体路径。
2. 为本期要呈现的对象建 `objects`，为真实资料建 `assets`；先确认路径存在。
3. 将连续表达同一关系的字幕归为一镜，写一句 `intent`，选一个机制。intent 是说明文字，不能代替 beats；不要承诺引擎没有实现的手势或操作。镜头从0覆盖到duration，不漏掉片尾人声。
4. 从字幕中找关键词的实测时点写 `beats.at`。准备动作可提前，核心结果在at落位；不知道词级时点时回到声音测量，不凭字数均分。
5. 为每镜选择 `presenter` 和 `transition`。开场人物可以full，材料重点可以pip或hidden。圆窗/窗口用在语境改变时，不必每句话都来一次。
6. 校验、按错误路径修复、编译、看实际样段。先改JSON；只有字典确实表达不了才写组件。

```shell
python scripts/validate_storyboard.py episode.json --mode draft --json
python scripts/compile_storyboard.py --input episode.json --out ../episode-draft --draft
cd ../episode-draft
npm ci
npm run check
npm run render
```

真人/数字人的正式片用测量后的时间和真实文件，移除 `--draft`，并通过 `--media-dir` 指定本期素材根目录。生产校验会拒绝缺声音或不合要求的来源状态，编译会拒绝引用不存在的素材；粗剪是否真实完成仍要对照实际工程与导出核实，不能仅为通过校验而改标记。

## 节奏与景别

镜头长度由要表达的关系决定。复杂动作至少给观众一次看清对象、一次看见变化、一次读懂结果的机会。长片在物体解释之间穿插人物回场和稳定读数；不要把16秒测试片的密度循环三分钟。

相机通过focus目标与动作时点追随当前对象。两个对象需要比较时，至少分别看清一次再恢复整体关系。画面中过多全文台词、重复字幕和装饰会削弱动作；标题只保留当前问题或判断。

不同主题的差异应体现在对象、真实资料、动作路线、机制组合、数量、时长和节奏上；只改配色与标签不算重新导演。

## 模型修复循环

每轮只修报告指出的字段及其依赖，保留已经正确的字幕与事实。重新校验通过后再渲染。结构通过不证明视觉好看；检查关键词、推近最大值、转场中间态、最长文字和结尾。视觉问题按 [修复配方](repair-recipes.md) 处理。

如果轻量模型连续无法正确提取语义、给出可靠时间或选择合适素材，保留已完成的工程并明确指出需要更强模型或人工处理的那一步。工具负责减少出错面，不承诺任何模型在任何选题都达到相同审美。
