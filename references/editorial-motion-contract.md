# 可移植的口播剪辑动效契约

本契约记录 `storyboard v2` 已实现的局部渲染能力。整体风格依据是[最初完整参考的剪辑方向](approved-editing-direction.md)，V3与净水器只提供部分物体、镜头、曲屏和漫画机制。原片本身大量使用真实UI、屏幕、图表和视频；应按内容组合，不能让一种固定软件界面或一种纸感插画统治全片。现有契约尚未完整覆盖原片的全部表达。

## 最短制作路线

1. 保留一条实际口播时间轴，先逐句对齐字幕。真人原素材先完成 ChatCut 粗剪；数字人记录 `roughcut: "skipped-digital"`。
2. 只规划本期开头 10–15 秒。若原片只有 10.7 秒，按实际长度交付，不拉长语音或补空白凑 15 秒。
3. 为每句填四列：原话 → 可见物件/证据 → 物体实际发生什么 → 镜头看哪里、怎样进入下一场。
4. 优先复用能准确表达本期语义的已有实现，素材可以是真实视频、UI、图表或原创图形。现有实现不足时扩展，不为迁就示例将所有内容改成同一种画法。
5. 在 `scene.editorial` 填构图；检查后用本期计划生成工程。不给输入时不会自动套用历史题材。

```bash
python scripts/validate_storyboard.py episode.json --mode production
python scripts/new_project.py --input episode.json --media-dir ./input --out ./opening
cd opening
npm ci
npm run check
npm run render
```

`npm run render` 会渲染输入计划的全部长度。因此这里的 `episode.json` 只包含准备让用户看的开头。确认这个实际样段之后，再扩展到全文。生成工程中的 `STYLE_TARGET.md` 保留视觉方向。

## 统一坐标和时间

- 画布输出为 1080×1920；下文所有设计坐标使用 **540×960**，渲染时等比例放大。
- 原有 `scene.start/end`、字幕及 `beats.at` 继续使用整片时间。
- 新增 `editorial` 内的所有 `at/start/end/enterAt/settleAt/threadAt/threadEnd/noteAt` 和 `transitionAnchor.start` 使用 **场景局部秒数**：`local = videoTime - scene.start`。
- 局部时间允许 `-1.5` 秒至场景长度。负数用于下一场尚在物体窗口里露出时的预演；进入画面的下一场继续按实际时间运动，不冻结在首帧。
- 图层 `x/y` 是左上角，`w/h` 是基础尺寸；旋转和缩放围绕图层中心。`keys` 可只写变化字段，其他字段继承上个关键帧。
- 图层与镜头关键帧必须严格按时间递增。相同时间的属性合成一个关键帧。数值必须有限，尺寸、缩放、镜头倍率为正，透明度为 0–1。

## 场景配置

```json
{
  "background": "paper",
  "title": "它为什么会变化",
  "eyebrow": "观察同一对象",
  "layers": [
    {
      "id": "seed-prop",
      "assetId": "seed-art",
      "x": 62, "y": 300, "w": 190, "h": 240,
      "rotation": -6, "shadow": true,
      "keys": [
        {"at": -0.25, "x": -190, "opacity": 0},
        {"at": 0.2, "x": 62, "opacity": 1},
        {"at": 1.2, "x": 280, "y": 246, "rotation": 9},
        {"at": 1.6, "x": 300, "y": 310, "rotation": 0}
      ]
    }
  ],
  "camera": [
    {"at": -0.25, "x": 157, "y": 420, "z": 2.4},
    {"at": 0.6, "x": 270, "y": 447, "z": 1}
  ],
  "connections": [
    {
      "id": "growth-route",
      "points": [{"x": 157, "y": 390}, {"x": 260, "y": 240}, {"x": 395, "y": 390}],
      "start": 0.3, "end": 0.9,
      "color": "#252722", "width": 2.5
    }
  ]
}
```

这是放在一个场景里的配置片段，不是完整 `episode.json`。`seed-art` 必须在本期根级 `assets` 声明并对应真实文件；名称只是展示种子话题如何复用能力，不要求别人的视频都讲种子。场景长度应覆盖配置中的全部时间。

`background` 支持 `paper / ink / comic`。不需要标题就省略 `title/eyebrow`。`layers` 按数组顺序绘制，后面的在前面之上；素材可包含自己的排版、笔触和立体结构。每个图层的 `assetId` 来自本期 `assets`。`foreground: true` 将该图层放到数字人之上、字幕之下，适合开场 Logo 纸片，不会让整个场景盖住人物。

主标题也可以随口播变化，避免第二句话仍停留在第一句标题。`titleKeys` 使用场景局部秒数，按时间严格递增，范围同其他关键帧；未提供时仍显示基础 `title/eyebrow`。每次变化用约 0.16 秒的淡出、淡入和轻微位移接力。省略新关键帧的 `eyebrow` 会保留上一条眉题，设置空字符串可清除。必须使用本期真实内容，不自动生成或补充事实。

```json
{
  "title": "还只是种子",
  "eyebrow": "生长记录",
  "titleKeys": [
    {"at": 1.4, "title": "已经发芽"},
    {"at": 2.7, "title": "第一片叶子", "eyebrow": "继续观察"}
  ]
}
```

`camera` 是全场景共享镜头，不是让每个物件独立随意缩放。聚焦点 `(x,y)` 映射到画面 `(270,447)`：

```text
screenX = 270 + (worldX - camera.x) * camera.z
screenY = 447 + (worldY - camera.y) * camera.z
```

根据话语的强调安排近景与回拉，不能把 2.4 倍推进当成每个镜头必用的固定参数。线条 `connections` 用至少两个世界坐标点形成平滑路径，并在指定区间绘出；让它表达关系，别只当装饰。

启用 `editorial` 后，旧的 `objectIds` 和 `beats` 可为空，旧机制的图标数量/默认网格要求不再强加。`mechanism` 仍保留为镜头意图标签。未启用 `editorial` 的旧工程行为保持原样。

## 物体表面接力到下一场

转场配置放在**离开的场景**上；`transition` 取 `window` 或 `circle`：

```json
{
  "transition": "window",
  "transitionAnchor": {
    "space": "layer",
    "layerId": "seed-prop",
    "rect": {"x": 22, "y": 90, "w": 142, "h": 94},
    "start": 1.9,
    "duration": 0.3,
    "borderRadius": 6
  }
}
```

这段对应一个长 **2.2 秒**的场景，例如 `start: 4.2, end: 6.4`。`1.9 + 0.3 = 2.2`，窗口完成时恰好交接下一场。`rect` 是物件基础尺寸内部真实可开窗的表面，不是整个物体包围盒；其位置随物件移动、旋转、缩放和共享镜头实时变换。`rect` 不能超出图层基础 `w/h`。窗口可以很小，不要求固定 88×64。

圆形接力可用 `space: "screen"`，`rect` 作为 540×960 屏幕内的锚点区域，圆心取其中心。这适合从便笺上的词、问号落点等位置切入漫画世界。屏幕锚点不跟随图层，若对象仍在移动应选择 `space: "layer"`。转场结束与场景结束允许最多一帧的舍入差异。

## 整屏曲面证据场景

```json
{
  "background": "ink",
  "layers": [],
  "evidence": {
    "assetId": "interview-frame",
    "title": "本期证据标题",
    "subtitle": "材料来源或必要说明",
    "note": "4h+",
    "noteAt": 0.95,
    "lensStrength": 138
  },
  "camera": [
    {"at": -0.2, "x": 270, "y": 447, "z": 1},
    {"at": 0.65, "x": 276, "y": 409, "z": 1.22},
    {"at": 1.2, "x": 270, "y": 440, "z": 1.05}
  ]
}
```

同一鱼眼场里包含边框、顶栏、来源画面和进度线；不是只扭曲一张图片。真实素材窗基准为 `x:-10, y:187, w:560, h:356`，按 cover 铺满，先裁好真实材料，不能裁掉需要看到的人脸或文字。自建边框是设计容器，不冒充网站截图。`assetId` 不存在会校验失败。

便笺有独立纸张厚度，位于世界坐标 `171,612,335,181`，绕中心 `338.5,702.5` 旋转 -6 度，入场历时 0.23 秒。它在鱼眼屏幕之外、共享镜头之内；做屏幕空间圆形转场时按上述镜头公式计算落点。`note` 是本期事实，不能原样照搬 `4h+`。

## 完整漫画世界和胶片红线

```json
{
  "background": "comic",
  "title": "追踪这个问题",
  "layers": [],
  "filmstrip": {
    "assetIds": ["frame-a", "frame-b", "frame-c", "frame-d"],
    "x": -18, "y": 489, "w": 576, "h": 166,
    "rotation": -5,
    "enterAt": 0.2, "settleAt": 0.8,
    "threadAt": 0.85, "threadEnd": 1.6
  }
}
```

胶片支持 2–12 个画面，允许重复引用同一来源。边框、齿孔、各帧宽度、穿线弯曲路径及末端线结按数量计算；不固定三张访谈图。素材实际显示在胶片里，整条胶片带惯性进入，红线逐帧穿过并收束。上方还需要本期的主物件，如问号、证据圆框、问题主体；不要把这段孤立配置当成每期完整画面。

`enterAt < settleAt`，`threadAt < threadEnd`，均在场景局部范围内。通常等胶片接近落稳再开始穿线，具体时间应匹配本期语音。不同镜头可以不用胶片，不必强行凑齐所有效果。

## 数字人与字幕

```json
{
  "presenter": "pip",
  "presenterStyle": {
    "shape": "portrait",
    "x": 24, "y": 678, "w": 126, "h": 165,
    "rotation": -3, "radius": 18
  }
}
```

人物是否出现、画面占比、圆形或竖向窗、位置及出入时点由本期内容与使用者要求决定，不把历史倾斜竖窗当成原片默认。引擎现有省略参数的回退值只为兼容旧工程，新片应明确设置 `presenter` 和需要的 `presenterStyle`。旁白使用同一完整音轨；出现的人物和字幕不随场景镜头或鱼眼变形。

## 给能力较弱模型的执行顺序

- 先做语义四列表，再选现成场景能力；逐项填资产、位置、时间，不从零重写渲染器。
- 数字人、录音和私有证据由使用者输入。只使用 `--media-dir` 内相对路径；包里不依赖作者磁盘或聊天记录。
- 每次先解决校验错误；未知字段会提示没有实现，拼错的 `rotatoin` 不会悄悄被当成成功。
- 对真实开头检查五个点：人还在讲；字幕对应语音；物件表达这句话；镜头看得到动作；下一场从上一场某个具体位置接出来。
- 完成必要成片检查后直接交实际 MP4；日常不要求逐帧对照、对比片或审查报告。只有具体异常、用户反馈不像或明确要求时才针对性比较。TypeScript 或结构检查不能代表用户已认可观感。

这套实现把稳定的动效计算和渲染交给代码，降低对模型临场编程的依赖；新材料是否恰当、整段风格是否符合预期，仍以真实样段检查和用户判断为准。
