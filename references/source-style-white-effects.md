# 白底机制：能力、选用与限制

这些组件提取自本项目已获得的参考视频中的具体动作结构。它们是根据观察重新实现的可编辑动画，不是恢复原作者工程。技术运行成功不代表原片风格已经得到用户认可。

源片时点只用于找到比对证据，不是新视频的固定时间轴。组件所有 `marks` 均为**本镜头内、动作达到结果的秒数**；对齐本期音频关键词后再填入。下面的秒数是无声校准样例，不可覆盖本期语音时间。

## `poster-route`：多份材料沿细线汇入一份结果

参考位置约 **1.867–6.733 秒**。适合“收集、提取、综合、整理成方法”等含义。

可见动作：纸质海报按不同高度和角度依次进入 → 摄影机推到选中海报的下缘 → 细线从原海报底部连续绘出 → 镜头拉回 → 多条非对称曲线进入同一个结果框。

- `content.items` 使用 3–5 个对象。3 个对象保留源片的错层比例；4–5 个自动缩窄排布，属于同规则的新排布。
- `selectedId` 选择近景跟随的对象；省略时选第一个。
- `item.image` 可接入本期海报、照片或材料图；原比例在卡片内裁切，不拉伸。不要把已烘焙字幕的整屏视频截图当海报。
- `content.result` 是汇合框中的短结果，如“旅行手记”“研究结论”。建议 2–6 个汉字。
- `content.body` 是小字号辅助句，最多显示前 26 个字符。

6 秒校准分配：`focus: 2.25, connect: 4.1, resolve: 5.2`。`focus` 达到近景；`connect` 附近完成主要连线；`resolve` 显出最终结果。若真实口播只有 3 秒，减少动作数量或换机制，不要把所有过程机械加速。

## `selection-build`：找到对象，沿着它完成操作与替换

参考位置约 **22.8–31.08 秒**。适合“准备内容、筛选方案、生成/处理、替换为自己的内容”的连贯叙述。

可见动作：斜置纸面逐字输入 → 3×3 候选图 → 放大镜靠近选中项，其余降低存在感 → **同一个选中图块**升至上方 → 下方代码窗逐行输入，与同一进度值同步 → 四格托盘进入 → 每个格子转到侧面再显露新内容。

- `content.body` 控制文档内容，建议 30–80 字；画面最多容纳 8 行。
- `items` 提供候选，`selectedId` 确定选中对象。显示 9 个候选位，少于 9 个时循环复用；因此正式成片最好准备 9 个有区别的素材。
- `content.code` 是画面的编辑器内容，不会执行；最多显示 9 行。建议每行不超过 40 个拉丁字符，给手机观看留可读性。
- 前 4 个 `items` 的 `replacementImage` / `replacementLabel` 控制翻面后的图文。需要“四个全部换成品牌”时，明确提供四个新素材，不要让模型仅替换标题。
- `content.prompt` 是托盘下面输入栏文字，建议不超过 18 个汉字；长句会自动缩小。
- `content.result` 是操作完成后的一句短结果。

10.4 秒校准分配：`document: 1.3, search: 3.0, select: 4.1, code: 6.7, replace: 9.3, resolve: 10.1`。`code` 是代码输入和进度达到 100%；`replace` 是最后一格翻面完成；二者都不是动作开始时间。

## `ui-handoff`：真实界面材料经过复制，成为下一步的输入

参考位置约 **75–95 秒**，重点为 **85.85–90.17 秒**的复制接力。适合“浏览内容、打开详情、复制引用、发送输入、取得结果”。

可见动作：轻质网页窗口进入 → 页面滚动，光标移向候选 → 详情浮层打开，原网页仍在背景 → 点击复制状态改变 → **同一个 URL 元素**从详情中脱离，移动并改变外形 → 聊天窗在后方展开 → 参考卡与逐字输入出现 → 发送 → 编辑式结果纸面。

- `items` 是网页卡片素材；`selectedId` 选择详情对象。
- `content.url` 是画面显示的地址；组件不发起该地址请求，也不执行登录、复制或远程接口。只显示输入内容，不能借动画声称真实操作已经成功。
- `content.prompt` 控制聊天输入，建议不超过 45 个汉字。
- `content.result` 是结果纸面的主要文字，建议 10–35 字；`body` 是结果辅助正文。
- 原片的仓库文件表和代码前景不是此模块的独立阶段。如果旁白讲到这些具体界面，需要扩展同一状态链或提供真实界面录屏，不应略过后宣称已经逐镜复刻。

14.8 秒校准分配：`browse: 1.5, select: 3.4, open: 5.3, copy: 7.8, paste: 9.4, send: 12.3, resolve: 14.0`。`copy` 时 URL 仍在详情中；`paste` 时它已落入聊天；`send` 时输入结束且按钮落点完成。

## 共同材质与改造边界

- 逻辑舞台宽 544。3:4 与 9:16 使用相同物体比例，增加上下间距并调整落点；不会把源片 544×720 强行拉长。
- 使用暖白纸面、细边线、柔阴影、黑色正文、局部暖橙、衬线编辑式标题；代码窗只在确实出现代码时使用深色。
- `content.emphasis` 可指定标题内需要局部暖橙着色的连续短语，必须原样出现在 `title` 中。由本期语义决定强调内容，不使用固定关键词表。
- 源片的照片、网站素材、品牌、局部动图并未内置。默认图形是本项目原生绘制的中性机制示意；其作用是验证动作结构，不是代表素材已经匹配本期语义。
- 带 `image` 的对象继承相同坐标、镜头和变换逻辑。需要保留素材内部动画时，应进一步接入视频或原生子组件；一张图片不能替代原片中持续变化的内部内容。
- 精确字体、原作者弹性曲线、源图像细节和全部音效未恢复。正式验收必须看连续样段，同时听已有口播；仅截几帧相似不构成通过。

实现位于 `assets/source-style-template/src/effects/WhiteEffects.tsx`。新增同风格镜头时可复用纸面阴影、类型排版、物体比例、曲线路径和共用 `motion.ts`，但必须围绕本期实际语义定义对象与动作，不能只换标签。
