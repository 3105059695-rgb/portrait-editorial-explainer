# 最高基准：最初原始参考的完整剪辑风格

用户喜欢的是最初提供的整条参考视频所呈现的视觉与剪辑感觉。后做的数字人 V3、净水器和软件界面样段，都只是对部分做法的尝试。某一段得到“可以”的反馈，只表示该段可接受，不授权用该段重新定义整个 Skill 的风格范围。

原始参考约140.5秒，内容为动效参考、代码复用与 Motion Face 的讲解。以下时间用于定位原片中实际出现的画面类别，不是新视频的固定时间轴。没有把私人参考原片放进公开包，也不要求调用者有作者电脑上的路径。

## 原片实际包含的表达范围

| 原片位置 | 实际可见内容 | 应保留的能力 |
|---|---|---|
| 约3–6秒 | 多张参考视频画面、衬线字排、连线与 skill 标签 | 编辑排版、真实画面拼贴、多对象关系；画面不必都做成插画 |
| 约9–18秒 | 深色代码背景、浅色终端窗、人物操作电脑和屏幕素材 | 软件界面、实拍/B-roll和图形包装之间切换，保留材料本身的质感 |
| 约21–33秒 | 想法灯泡、文档、参考网格、放大镜、代码进度、输入栏、素材换成Logo、REMIX字排 | 同一讲述链中改变表达形式，UI状态与素材变化直接解释内容 |
| 约36–63秒 | 原版/改版上下对比、难点卡、筛选网格、token粒子、数字、条图和圆环 | 比较、筛选、数量与成本由不同信息图表达；不只是同一标题下替换中央物件 |
| 约66–85秒 | 透视排列的画廊、弯曲网站特写、多层窗口和GitHub画面 | 平面信息与空间镜头结合，资料画面、视差、前后层次共同参与剪辑 |
| 约88–112秒 | 手绘浏览器外框、真实网站内容、文档摘录、手机、评价贴纸和标注 | 写实素材与图形外壳可以融合；UI是重要组成，并非只能偶尔辅助使用 |
| 约115–140秒 | 彩色放射背景、像素猫、胶片、方块、机器人、钱币图表、杯子和人物群体 | 漫画只是其中一组表达；后段用更多颜色、符号与场景变化推动说明和情绪 |

这些是完整风格的范围，不是必须按顺序执行的七幕。短样段按内容选取需要的几种方式即可；不得为了凑多样性机械塞入所有类别。

## 原片怎样把不同画面组织成同一支视频

- 排版清楚、有主次和留白，关键词与当前视觉焦点对应；衬线字、无衬线字、资料原生文字和漫画字可以各司其职。
- 清爽浅底、深色资料、真实影像和鲜明彩色段落形成变化。颜色与材质随场景用途选择，不把整片固定为绿色纸感或紫色漫画。
- 近景、全局、平面和透视空间交替使用；镜头带观众去看变化发生的位置。
- 人物、真实图像、屏幕、文档、图形与文字可以融合。物件运动、状态变化、窗口接力、图形转场和直接剪切都可以用，不要求每次都从一个物体表面开窗。
- 画面密度和节奏随信息改变，有连续变化，也有读清内容的停留；不能用统一三秒一页或固定四幕代替剪辑。

用户最看重的是正常观看时的整体感觉。组件数量、可以修改文字或几张漂亮静帧，都不足以证明保留了这套感觉。

## 这次必须纠正的收窄

将“有纸感、有粗描边物件、能推拉、有转场”当成全部目标，会把所有题材做成同一种插画讲解。净水器样段出现了这种收窄：相近的底色、同一位置的大标题、同一套描边物件贯穿全片。它可以保留为一组局部做法，不能成为 Skill 的默认总风格。

同样，数字人 V3 的“人物→钱币/公司→访谈→漫画”只是一份旧编排；RC2 的应用工作台只覆盖界面状态变化。两者都不能取代原始参考。此前入口中“数字人 V3 是默认视觉基准”的表述已撤销。

新增题材时先决定每段最适合的材料与表现方式，再设计动作和转场。比如产品话题可以结合真实产品或操作素材、空间信息图、局部结构动画和重点字排，按内容组织；不能默认把一切都重新画成同一种道具。

## 人物与生产流程

用户给数字人/口播时，保留声音主线，根据镜头需要安排全屏、画中画或暂时让位给素材。竖向窗、圆窗、占比和出现位置由本期内容与用户要求决定，不将自己旧样段的人物窗当作原片风格的必要条件。

真人原始口播先经 ChatCut 粗剪，数字人默认跳过；已有粗剪和最终配音直接采用。先交本期真实开头10–15秒。日常掌握方向后直接创作，只做必要成片检查；首次学习新参考、用户指出不像或明确要求时才针对性定位差异，不默认制作对照图、对比片或审查报告。

## 实现只是工具，当前覆盖仍有边界

- assets/adaptive-template 的 scene.editorial 已提供素材图层、相机、精确表面开窗、连续进入下一场、曲面资料、胶片红线、标题变化和人物窗；这些可复用，但不限定美术风格。
- 软件界面、信息图和图形状态变化可查 [UI组合契约](ui-composition-contract.md)、基础分镜机制与相应源码；选用前确认实际渲染支持，不能把说明文档当作已经实现的效果。
- assets/presenter-v3-template 是局部机制的历史源码参考，通过显式 --case presenter-v3 复制；新题不沿用其选题或固定编排。
- 未覆盖的实拍组合、空间镜头或其他设计应使用合适材料并补相应实现。现有模板并未完整覆盖原片全部视觉范围，不得声称“所有模型已经能稳定复现整套风格”。

降低模型负担的方向是提供更多可靠的可组合实现与明确的选用方法，同时保留原片的丰富表达范围。不能通过把风格简化成一种画法来降低任务难度。
