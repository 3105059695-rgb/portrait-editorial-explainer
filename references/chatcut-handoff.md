# ChatCut 粗剪与动效工程衔接

仅在真人原始口播需要粗剪时读取。数字人默认跳过语音清理；已粗剪素材先检查现有版本。完整叙事规则见 [持续口播生产](presenter-workflow.md)。

## 先确认现有能力

Skill 文本可以直接安装，ChatCut 账号和连接不能随仓库转移。通过当前代理环境查看 ChatCut 插件/工具是否可用，并使用使用者授权的工程。不要要求使用者在聊天里粘贴令牌；按照其客户端的连接方式完成授权。未连接时保留待剪状态、指出缺失能力，不声称已经执行。

若当前环境有 ChatCut 的安装说明和口播指南，优先按它们的实际接口操作。下面是2026-10-12可见能力名称与职责，不是固定 API 参数契约，调用时必须读取实时工具 schema。

| 阶段 | 可见能力示例 | 完成证据 |
| --- | --- | --- |
| 找到用户指定工程 | `list_projects`、`target_project`、`read_project` | 实际工程标识、画布/时间轴与用户目标一致 |
| 导入或复用素材 | 当前 asset-import 工作流、`browse_assets`、`inspect_asset` | 素材真实存在、时长与转写状态可读；已导入不重复导入 |
| 读口播并设计保留内容 | `read_script` | 已读取对应素材/时间轴的文字稿，核对人名、术语和重复试录 |
| 应用剪辑 | `clean_script`、按当前 script 编辑工作流修改后 `apply_script` | 回读时间轴确认剪切已落地；文字建议不等于实际剪辑 |
| 音频衔接 | 结构定稿后 `smooth_audio` | 修改切口无吞字、突兀音量和不必要的空画面；后改结构需复查 |
| 输出交接 | `submit_export`、`track_export` | 实际完成的导出文件或可复现剪辑映射；创建导出任务不等于已完成 |

如果工具要求在编辑器里打开目标工程，先完成其返回的页面交接，再修改时间轴。不要覆盖另一工程或把素材库中的存在误认为已经放进时间轴。

## 粗剪的默认强度

处理明确口误、无效重复、失败试录、开关录制废片和过长空等。保留完整语义、过渡词、自然呼吸、情绪和强调。短自然停顿不批量清零；不擅自改稿、重排观点或使用加速掩盖问题。无法判断某段是否可删时，保留或做更小的剪切。

默认同步裁切画面与人声；保留段落速度为1。需要语音清理不等于要求重新配音或克隆声音。粗剪结束先检查实际切口，然后继续已授权的后续制作；遵循使用者当次对审阅节点的要求。

## 交给 Remotion 的两条路径

**路径 A：剪后中间片。** 从真正定稿的 ChatCut 时间轴导出人物视频与匹配人声，读取实际时长。重新对齐字幕到该人声；人物视频作为画面静音，一份匹配的主音轨输出声音。不要误配回原始未剪音频。

**路径 B：原片加剪辑映射。** 保留原素材，记录每个片段的源入/出点、剪后入/出点、速度与对应 cue。由本期 Remotion 工程根据同一映射组装画面和声音。参考 [映射示例](../examples/roughcut-map.json)，该 JSON 仅为交接格式示意，不会自动驱动包内历史模板，也不是 ChatCut 导出结果。读取 NLE/XML 时须处理其帧率与单位，不能直接把毫秒当秒。

两条路径均使用剪后时间作为字幕、动作、B-roll、音效、音乐长度和 Root 时长的唯一坐标系。后续删除或调整片段时按映射重新计算；不能给全部字幕简单加一个固定偏移量。

## 核对后再进入动效

- 保留的每个语义单元仍然完整，实际删减与计划一致。
- 声画同步，无意外黑帧、吞字、重声或两条同人声。
- 有实际可读的剪后文件或可靠映射，以及对应声音和时长。
- 记录素材来源与删减原因，保留原始媒体和可编辑工程。
- 若导出、转写或连接未成功，准确报告对应未完成项；不把失败的上游步骤用占位画面掩盖。
