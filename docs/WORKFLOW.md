# 从本期素材到可编辑成片

这一页说明正式制作时每一步的输入、动作与交接结果。它不要求你把工作拆成固定等长的镜头，也不把历史样例视为新一期已经完成的剪辑。

**日常默认直接创作。** 读取已确认的剪辑规则后，按本期口播写动作并用 Remotion 实现，完成必要成片检查，交付开头供使用者观看。只有首次学习参考、收到明确的“不像”反馈，或使用者要求复刻对照时，才做针对性比较；不把反复出对照图、写分析报告或独立审查变成每期前置步骤。

按语义在真实视频、UI/网站、排版、概念图形、图表、窗口/画廊和漫画之间选择表达；不要求每10秒出现全部类型。人物布局按本期要求安排，不预设全程某种小窗。

返回 [README](../README.md) · [安装教程](INSTALL.md) · [V2 分镜规范](../references/storyboard-contract.md)

## 1. 先认清本期输入

把素材位置、主题、输出比例和必须保留的内容交给 Agent，可直接填写[本期输入表](../examples/episode-brief.md)。如果有已认可的工程、字幕或声音，一起提供。用实际媒体信息检查时长、分辨率、帧率和音轨，不能只根据文件名或人物外貌判断素材类型。

| 输入类型 | 正确入口 | 本阶段的交接结果 |
| --- | --- | --- |
| 真人原始口播 | ChatCut 粗剪 | 剪后画面、匹配人声、可编辑剪辑与时间映射 |
| 数字人口播 | 默认跳过语音粗剪 | 既有定稿视频／声音及核对后的时长 |
| 已经粗剪的口播 | 检查并沿用 | 当前可用剪后版本及已有时间信息 |
| 只有旁白 | 以旁白为主时钟 | 最终声音母带、校对稿与时间信息 |
| 只有稿件 | 先做语义分镜 | 标明估算时点的视觉草案；最终录音后校准 |

本期人物、参考风格视频、证据截图、B-roll 是不同用途。参考片中的人像不能自动成为本期素材，占位图也不能当作真实访谈证据。

若稿件涉及最新产品、新闻或具体数字，先核实当前事实与来源。历史案例字幕中的人物、观点和日期只说明旧案例如何编排，不是本期的事实材料。

## 2. 真人原始口播先在 ChatCut 粗剪

这一步需要当前 Agent 有可用且经过使用者授权的 ChatCut 连接。按宿主实际提供的 ChatCut 插件说明执行；不同版本的界面与能力可能不同，本教程不规定固定按钮位置。能力与交接检查参考 [ChatCut 粗剪衔接](../references/chatcut-handoff.md)。

有现成 ChatCut 工程时先读工程和已导入媒体；素材已有转写时先复用并校对。对照真实音画决定切口，不能仅用静音阈值批量“去空白”。

| 通常可去除 | 应保留或谨慎处理 |
| --- | --- |
| 开关录制前后的废片 | 完整观点与论证顺序 |
| 明确口误及重新说对之前的失败试录 | 有意义的连接词、情绪和强调 |
| 无效重复、明显多余口癖 | 自然呼吸、必要停顿与可懂度 |
| 与表达无关的过长等待 | 自然手势、嘴型连续性与保留片段原速 |

粗剪时画面与原声一起切。完成后检查每个改动切口，关注吞字、爆音、嘴型错位、黑帧、手势跳变和语义连接。只给出删减建议、改完文字稿或导入成功，都不能算实际粗剪完成。

保留原媒体和可编辑工程，再采用下面一种方式交给 Remotion：

1. **导出中间视频**：导出粗剪后的画面与声音，在 Remotion 中接入同一剪后版本。默认模板更适合这条明确的媒体交接路径。
2. **保留片段映射**：由 Remotion 按同一组源片段入／出点读取原媒体。需要实现对应的剪辑映射代码，模板的默认单个媒体路径不会自动完成这件事。

两个软件不会因为安装了这个 Skill 就自动共享时间轴。实际采用哪一种方式，应写进本期工程说明。

建议保存 `roughcut-edl.json` 或等价表格，记录源文件、源入／出点、剪后入／出点与删减说明。完整示意见 [roughcut-map.json](../examples/roughcut-map.json)。下面只是可读的数据示意，**不是 ChatCut 承诺自动导出的标准格式，也不是现有脚本的输入格式**：

```json
{
  "purpose": "DEMO ONLY - times are seconds",
  "segments": [
    {
      "sourceAsset": "raw-presenter.mp4",
      "sourceStart": 1.2,
      "sourceEnd": 6.8,
      "outputStart": 0.0,
      "outputEnd": 5.6,
      "playbackRate": 1.0,
      "cueIds": ["intro-01"],
      "note": "保留第一段完整表达；前面的录制准备已去除"
    }
  ]
}
```

如果 ChatCut 不可用，可以先检查素材、做事实核对、准备语义分镜与动效工程；应将粗剪交接列为尚未完成。不要悄悄把未经处理的原片改名为“粗剪版”。使用者若提供现成粗剪素材，可以走已粗剪分支继续。

## 3. 锁定唯一的最终声音时间轴

真人任务以粗剪后人声为主时钟；数字人以定稿声音为主时钟。之后的字幕、关键动作、音乐和工程总长度全部依从这个时钟。

“保留原人声”表示保留说话者声音、表达与保留片段的原速，并不表示必须保留录制废片。也不表示可以把剪后画面与未剪原音轨混在一起。

以实际声音校对转写，尤其是人名、品牌、术语、数字和否定词。句子开始、关键词出现、动作结果落位是不同层级；没有词级测量时不要将按字数均分的时点称为精准对齐。

后续若删掉一句或改变停顿，应重新映射受影响的字幕与动作。多段删改通常不能靠“全部提前 0.5 秒”解决。

## 4. 把口播变成语义动作

先写四列表，再选择素材和镜头。例如一段“净水器安装准备”的口播可以这样设计：

| 说了什么 | 持续存在的物体／证据 | 可见动作 | 镜头关注 |
| --- | --- | --- | --- |
| 先检查接口和可用空间 | 接头、橱柜的空间关系 | 接头特写后回拉，接着聚焦安装空间 | 景别变化让观众看清两个检查对象 |
| 滤芯要对准位置 | 同一根滤芯与机身 | 滤芯沿弧线接近，再进入机身 | 跟随移动路径，落位时留短暂停顿 |
| 按对应产品说明书操作 | 实际说明资料，或明确标注的示意 | 从机身水窗展开资料画面 | 整个证据画面曲面聚焦，保留可读性 |
| 把步骤连起来看 | 接口、空间、安装、出水四个过程画面 | 胶片进入，红线逐格连接 | 回拉看完整关系，再聚焦结果 |

对应的自制产品 UI 标“示意”；使用真实 UI 时保留可读的操作与结果，不用无关终端或代码段装饰。

共同空间、对象接力、速度变化和镜头焦点是可选方法。新主题应按完整参考的丰富表达选择实际素材和镜头，不能用旧求职路线或净水器插画布局处理所有主题。

整体方向以[原始参考的剪辑方向](../references/approved-editing-direction.md)为准，[V3机制说明](../references/approved-presenter-v3.md)只解释部分可复用动作：

- 使用人物时保留脸与重要手势；是否开场出现、缩小、移位或回场按本期表达安排。
- 一次推近对应当前被讲述的对象，之后回拉建立关系；大运动后留阅读时间。
- 证据画面可采用曲屏等效果，但文字、数字和操作状态应清楚。
- 漫画段用具体动作解释抽象关系；前一物体可以展开为下一场窗口。
- 字幕保持稳定屏幕坐标，避免跟着镜头缩放、曲面化或旋转。

长口播应有紧松变化，不能把十秒样例的密度连续重复几分钟。

## 5. 模型写本期分镜，通用引擎执行动作

先按[原始参考方向](../references/approved-editing-direction.md)选择本期表达，再用[V2分镜契约](../references/storyboard-contract.md)和[Schema](../references/storyboard.schema.json)填写支持的部分。`src/episode.json` 统一字幕、场景和动作；表面开窗、持续入场、胶片和人物窗等可直接复用。它们不是完整原片能力，其他需要的视频、UI状态、图表、画廊或漫画表达应补充相应实现，不能一律替换成纸感物件。

**第一份 `episode.json` 只写本期真实开头 10–15 秒。** 起点为 0，声音、字幕、场景与动作沿用本期同一时钟，终点落在完整语义处。不要先传全片再指望脚本自动截断；使用者确认样段后才扩展全片。

把一句话拆成主语、动词、对象关系和需要展示的证据，再选择机制。例如“把散落的问题按主题整理”对应同一组 message 对象进入 folder；“把整理结果交给负责人”对应 document 沿 route-transfer 路径移动。不能仅因句子换了就切一张新标题卡。

推荐设计顺序：

1. 写本期 `captions`，每句有稳定 ID、实测起止点。
2. 建立 `assets`，登记本期原创插画、真实资料或明确示意的相对路径与来源；同一物件尽量持续使用同一素材身份。
3. 按语义分段写 `scenes`，从零连续覆盖 `duration`，镜头数量不固定。
4. 每镜填写 `intent`、`mechanism` 和 `cueIds`，说明画面要让观众理解什么。按参考风格直接构图时，用 `editorial.layers` 安排本期物件，再用 `editorial.camera` 安排景别。
5. 需要基本自动布局时使用 `objects`、`objectIds` 和 `beats`；`beats` 使用全片绝对秒数。使用直接编排的 `editorial` 时，`objects`、`objectIds`、`beats` 可为空，动作由本期图层和镜头关键帧承担；不能只写一个动作名称而不给实现数据。
6. 填入 `source`、`media`、`timing` 与配色。没有最终声音的输入必须标为 estimated/demo，不能写 measured。

直接编排的完整例子见[职业主题校准](../examples/storyboards/editorial-career-opening.json)与[净水器安装](../examples/storyboards/editorial-water-opening.json)。它们使用不同素材、布局和动作来运行同一套机制。旧的[客户问题](../examples/storyboards/customer-questions.json)、[基础净水器](../examples/storyboards/water-filter.json)和[文物记录](../examples/storyboards/artifact-recording.json)仅帮助理解自动布局的基础结构，不替代本期风格编排。

`editorial` 的坐标为 **540×960逻辑舞台**；所有图层、镜头、标题和胶片关键帧使用**本场局部秒数**，不要误填全片时间。负时间最低为 `-1.5` 秒，用于下一场在窗口里提前开始运动；到场景起点继续推进，不重置时间。字幕、场景起止点及基础 `beats` 仍使用全片时间。

| 设计需要 | 本期字段 | 检查重点 |
| --- | --- | --- |
| 放大具体物件，再回拉建立关系 | `editorial.layers`、`editorial.camera` | 图层围绕自身中心旋转缩放，镜头控制整个世界；特写须对准实际被讲述的细节 |
| 同场景随台词换重点标题 | `editorial.titleKeys` | 按本场时点提供 `title` 和可选 `eyebrow`，不要把标题变化当成唯一动画 |
| 从某个真实表面进入下一场 | `transitionAnchor` | 用 `space: "layer"`、`layerId` 和层内 `rect` 精确选中表面；起点加时长应落在本场结束 |
| 让下一场在窗口内就有动作 | 下一场负时间图层／镜头关键帧 | 开窗前、中、后均有连续内容，下一场不是冻结截图 |
| 资料与界面整体曲面聚焦 | `editorial.evidence` | 用本期资料或明确示意，曲屏不能令核心文字和证据失读 |
| 胶片入场并逐格连线 | `editorial.filmstrip` | 提供2–12个本期画面，分别安排入场、落稳、连线起止时间 |
| 按内容安排人物 | `presenter`、`presenterStyle` | 按本期要求选择全屏、小窗或隐藏，以及形状、尺寸与位置；不套用历史默认 |

默认人物与字幕处于镜头、曲屏滤镜之外。前景纸片可用图层 `foreground: true` 放到人物上方，但必须避开脸部和关键手势。人物小窗与开窗衔接应查看中间帧，不能只看两个端点。

较轻模型也应优先沿用这套数据和组件：换本期素材、关系和时点，经校验后渲染查看。示例的旧剧情、固定道具和总时长没有优先权。本仓库没有跨模型盲测保证；完成结构校验不等于已经完成合格剪辑。

人物、声音、音乐与图像路径相对于 `--media-dir` 指定的素材目录。示意目录：

```text
episode-work/
├── episode.json
├── media-root/media/
│   ├── presenter-final.mp4
│   ├── voice-final.wav
│   └── evidence.png
├── roughcut-edl.json
└── SOURCES.md
```

相应 JSON 使用 `media/presenter-final.mp4`、`media/voice-final.wav`，不能写电脑绝对路径、URL、`../` 或 `public/` 前缀。提供图片时在 `assets` 登记路径、来源与用途，由对象 `assetId` 或场景 `evidenceAssetId` 引用。

人物视频默认静音播放，人声只从 `media.voice` 输出一次。人物和声音必须来自同一最终时间轴。只有带声音的最终人物视频时，可在自己的工作目录提取独立人声轨：

```powershell
ffmpeg -n -i "media-root/media/presenter-final.mp4" -vn -c:a pcm_s16le "media-root/media/voice-final.wav"
```

这只提取音轨，不会粗剪、分离混合 BGM 或校正嘴型。媒体时长不足应修复实际文件或重排本期分镜，不能靠延长 JSON 伪造有效画面。

## 6. 校验、修复、编译

在下载的 Skill 仓库根目录执行，路径换成本期实际位置：

```powershell
python -X utf8 scripts/validate_storyboard.py ../episode-work/episode.json --mode production --json
python -X utf8 scripts/new_project.py --input ../episode-work/episode.json --media-dir ../episode-work/media-root --out ../episode-opening
cd ../episode-opening
npm ci
npm run check
npm run test:motion
```

JSON 校验器给出具体字段位置与错误；模型应按[修复表](../references/repair-recipes.md)修改后再运行。比如 cueId 不存在就修正引用，动作早于台词就检查真实关键词时点，缺少真实材料就补材料或转为明确的草案，而不是关闭规则。

只有视觉草案时，校验改为 `--mode draft`，编译加 `--draft`。草案可以没有声音，但引用了路径的文件仍需存在；渲染带明确的草案标识。

第一次安装可先从仓库根目录运行公开原创净水器示例，验证换目录后仍可使用：

```powershell
python -X utf8 scripts/new_project.py --input examples/storyboards/editorial-water-opening.json --media-dir examples/media --out ../water-opening --draft
cd ../water-opening
npm ci
npm run check
npm run test:motion
npm run render
```

职业主题校准使用同样命令，把输入换成 `examples/storyboards/editorial-career-opening.json`，输出另用一个空目录。两个示例均不需要私人媒体或作者的绝对路径。`test:motion` 检查关键帧、镜头和表面转场的运算；它不播放声音，也不代替画面复核。

入口调用编译器先预检，再把通用源码、锁文件、引用素材和本期 JSON 复制进新的空工程，并附上 `STYLE_TARGET.md`。生成的 `BUILD_REPORT.json` 记录输入及素材摘要、模式和校验结果。数据中的 `duration` 和 `fps` 决定总帧数，无需每期手改 `Root.tsx`；字幕与动作直接来自同一 `episode.json`。无输入时入口会报错；`--case` 仅用于显式查看校准案例。

直接编辑新工程的 `src/episode.json` 也能预览变化。正式交付仍应对最终这份 JSON 再跑校验；大幅修改应重新编译到另一个空目录，以便保留版本和来源记录。编译器不会覆盖非空输出目录。

校验器不能证明实际口播同步、粗剪真的执行过、事实正确或素材获准使用。生产模式中的状态标记必须来自实际工作。已有旧版 `timeline.json` 的项目可继续用[历史时间轴检查器](../references/timing-format.md)，但它不是 V2 schema，不能直接输入新编译器。

## 7. 处理声音与字幕安全区

保留一份声音母带作为合成基准。BGM 与音效应服从人声清晰度和语义落点，不为踩节拍随意加速口播。默认示例没有音乐或动作音，历史案例提到的 BPM 与音效数量也不是必须复刻的标准。

字幕应准确、读得完且不遮关键内容。检查：

- 深浅背景切换的中间帧，是否出现浅底白字或深底黑字。
- 长句换行、数字与专有名词，是否被人物、手势、证据或边界遮住。
- 目标播放器／平台交互区域，是否会盖住底部字幕；模板坐标不是通用平台安全保证。
- 人物转为小窗时，脸、嘴与重要手势是否仍清楚。

只有使用者明确要求换声、生成头像或数字人时，才讨论相应服务、授权和费用。当前 Skill 不附带私人声音或默认人物。

## 8. 预览、导出、检查

在新工程目录运行：

```powershell
npm run check
npm run test:motion
npm run dev
```

预览时先看开头、每个关键词落点、转场的前／中／后状态及结尾；根据画面修改后再导出：

```powershell
npm run render
```

默认通用工程脚本导出 `out/adaptive-portrait.mp4`。**该命令渲染整个传入的分镜，不会自动截取开头。** 第一轮只传入准备好的0秒起10–15秒计划，直接用已掌握的镜头、物件动作和转场完成本期剪辑；检查播放、字幕和必要衔接后，交给使用者观看。收到样段反馈后再延展全片；需要校准的具体差距再针对性比较。新一期可以在本期工程中改输出名称，但交付说明必须与真实文件一致。

检查媒体信息和完整视频解码的示例：

```powershell
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate -of json "out/adaptive-portrait.mp4"
ffmpeg -v error -i "out/adaptive-portrait.mp4" -f null -
```

终端无解码错误只说明媒体能解码，不能证明台词正确、音画同步或视觉好看。抽听真实音轨与所有修改切口，若未完整听看，应写明抽查范围。

日常不要求另写审查报告。确实需要记录检查结果时，各结论依据不同：

| 结论 | 支撑它的实际证据 |
| --- | --- |
| 源码／时间结构通过 | TypeScript、时间轴检查的实际返回结果 |
| 导出完成且可解码 | 输出文件、媒体参数、完整解码结果 |
| 视觉抽查完成 | 检查过的具体时间点与发现／修复 |
| 完整音画复核完成 | 确实从头到尾听看后的记录 |
| 本期风格被认可 | 使用者对本期版本的实际反馈 |

不要把一个结论代替另一个。Skill 或模板的历史检查也不能作为本期成片检查记录。
