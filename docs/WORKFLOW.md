# 从本期素材到可编辑成片

这一页说明正式制作时每一步的输入、动作与交接结果。它不要求你把工作拆成固定等长的镜头，也不把历史样例视为新一期已经完成的剪辑。

返回 [README](../README.md) · [安装教程](INSTALL.md) · [时间轴完整规范](../references/timing-format.md)

## 1. 先认清本期输入

把素材位置、主题、输出比例和必须保留的内容交给 Agent，可直接填写[本期输入表](../examples/episode-brief.md)。如果有已认可的工程、字幕或声音，一起提供。用实际媒体信息检查时长、分辨率、帧率和音轨，不能只根据文件名或人物外貌判断素材类型。

| 输入类型 | 正确入口 | 本阶段的交接结果 |
| --- | --- | --- |
| 真人原始口播 | ChatCut 粗剪 | 剪后画面、匹配人声、可编辑剪辑与时间映射 |
| 数字人口播 | 默认跳过语音粗剪 | 既有定稿视频／声音及核对后的时长 |
| 已经粗剪的口播 | 检查并沿用 | 当前可用剪后版本及已有时间信息 |
| 只有旁白 | 以旁白为主时钟 | 最终声音母带、校对稿与时间信息 |
| 只有稿件 | 先做语义分镜 | 标明估算时点的视觉草案；最终录音后校准 |

本期人物、参考风格视频、证据截图、B-roll 是不同用途。参考片中的人像不能自动成为本期素材，占位图也不能当作真实访谈证据。

若稿件涉及最新产品、新闻或具体数字，先核实当前事实与来源。历史案例字幕中的人物、观点和日期只说明旧案例如何编排，不是本期的事实材料。

## 2. 真人原始口播先在 ChatCut 粗剪

这一步需要当前 Agent 有可用且经过使用者授权的 ChatCut 连接。按宿主实际提供的 ChatCut 插件说明执行；不同版本的界面与能力可能不同，本教程不规定固定按钮位置。能力与交接检查参考 [ChatCut 粗剪衔接](../references/chatcut-handoff.md)。

有现成 ChatCut 工程时先读工程和已导入媒体；素材已有转写时先复用并校对。对照真实音画决定切口，不能仅用静音阈值批量“去空白”。

| 通常可去除 | 应保留或谨慎处理 |
| --- | --- |
| 开关录制前后的废片 | 完整观点与论证顺序 |
| 明确口误及重新说对之前的失败试录 | 有意义的连接词、情绪和强调 |
| 无效重复、明显多余口癖 | 自然呼吸、必要停顿与可懂度 |
| 与表达无关的过长等待 | 自然手势、嘴型连续性与保留片段原速 |

粗剪时画面与原声一起切。完成后检查每个改动切口，关注吞字、爆音、嘴型错位、黑帧、手势跳变和语义连接。只给出删减建议、改完文字稿或导入成功，都不能算实际粗剪完成。

保留原媒体和可编辑工程，再采用下面一种方式交给 Remotion：

1. **导出中间视频**：导出粗剪后的画面与声音，在 Remotion 中接入同一剪后版本。默认模板更适合这条明确的媒体交接路径。
2. **保留片段映射**：由 Remotion 按同一组源片段入／出点读取原媒体。需要实现对应的剪辑映射代码，模板的默认单个媒体路径不会自动完成这件事。

两个软件不会因为安装了这个 Skill 就自动共享时间轴。实际采用哪一种方式，应写进本期工程说明。

建议保存 `roughcut-edl.json` 或等价表格，记录源文件、源入／出点、剪后入／出点与删减说明。完整示意见 [roughcut-map.json](../examples/roughcut-map.json)。下面只是可读的数据示意，**不是 ChatCut 承诺自动导出的标准格式，也不是现有脚本的输入格式**：

```json
{
  "purpose": "DEMO ONLY - times are seconds",
  "segments": [
    {
      "sourceAsset": "raw-presenter.mp4",
      "sourceStart": 1.2,
      "sourceEnd": 6.8,
      "outputStart": 0.0,
      "outputEnd": 5.6,
      "playbackRate": 1.0,
      "cueIds": ["intro-01"],
      "note": "保留第一段完整表达；前面的录制准备已去除"
    }
  ]
}
```

如果 ChatCut 不可用，可以先检查素材、做事实核对、准备语义分镜与动效工程；应将粗剪交接列为尚未完成。不要悄悄把未经处理的原片改名为“粗剪版”。使用者若提供现成粗剪素材，可以走已粗剪分支继续。

## 3. 锁定唯一的最终声音时间轴

真人任务以粗剪后人声为主时钟；数字人以定稿声音为主时钟。之后的字幕、关键动作、音乐和工程总长度全部依从这个时钟。

“保留原人声”表示保留说话者声音、表达与保留片段的原速，并不表示必须保留录制废片。也不表示可以把剪后画面与未剪原音轨混在一起。

以实际声音校对转写，尤其是人名、品牌、术语、数字和否定词。句子开始、关键词出现、动作结果落位是不同层级；没有词级测量时不要将按字数均分的时点称为精准对齐。

后续若删掉一句或改变停顿，应重新映射受影响的字幕与动作。多段删改通常不能靠“全部提前 0.5 秒”解决。

## 4. 把口播变成语义动作

先写四列表，再选择素材和镜头。例如一段“AI 整理客户问题”的口播可以这样设计：

| 说了什么 | 持续存在的物体／证据 | 可见动作 | 镜头关注 |
| --- | --- | --- | --- |
| 客户的问题散在聊天里 | 一组经过必要处理的真实聊天条目 | 目标问题逐条被选中 | 推近被选行，保留上下文 |
| 先把问题整理出来 | 同一组已选条目 | 条目移动进入整理窗口 | 跟随移动路径 |
| 按主题分成几组 | 原条目与分类标题 | 条目归入对应分组 | 回拉看清组间关系 |
| 看看还有哪些没回答 | 仍是刚才的分组 | 未答条目被明确标出 | 推近结果并停留供阅读 |

对应的自制产品 UI 标“示意”；使用真实 UI 时保留可读的操作与结果，不用无关终端或代码段装饰。

复用 V3 的是共同空间、对象接力、速度变化和镜头焦点。新主题应改变开场事件、关键证据、道具与动作。不能把旧公文包换一个标签，就把相同求职路线用于所有主题。

具体风格可参考[视觉语法](../references/visual-grammar.md)与 [V3 机制说明](../references/approved-presenter-v3.md)：

- 开场保留人物的脸与重要手势；人物画面随解释需要缩小、移位或回场。
- 一次推近对应当前被讲述的对象，之后回拉建立关系；大运动后留阅读时间。
- 证据画面可采用曲屏等效果，但文字、数字和操作状态应清楚。
- 漫画段用具体动作解释抽象关系；前一物体可以展开为下一场窗口。
- 字幕保持稳定屏幕坐标，避免跟着镜头缩放、曲面化或旋转。

长口播应有紧松变化，不能把十秒样例的密度连续重复几分钟。

## 5. 新建工程并接入本期媒体

从下载仓库根目录创建本期工程：

```powershell
python -X utf8 scripts/new_project.py --case presenter-v3 --out "../episode-001"
cd "../episode-001"
npm ci
```

将最终可用的媒体放入该工程的 `public/media/`。使用易识别的文件名，保留素材来源记录。建议结构如下，文件名可以自行调整：

```text
episode-001/
├── public/media/
│   ├── presenter-final.mp4
│   ├── voice-final.wav
│   └── reference-evidence.png
├── src/
├── timeline.json
├── roughcut-edl.json        # 真人粗剪任务才需要，或等价映射表
├── TIMELINE.md
└── SOURCES.md
```

这些本期记录文件需要自行创建，复制脚本不会自动生成真实转写、剪辑映射或素材来源。

编辑 `src/mediaConfig.ts`，路径相对于 `public/`：

```ts
export const mediaConfig: MediaConfig = {
  presenterVideo: 'media/presenter-final.mp4',
  voiceTrack: 'media/voice-final.wav',
  referenceImage: 'media/reference-evidence.png',
};
```

注意：

- 不写 `public/media/...`，不写自己机器的绝对路径；路径应与文件大小写一致，便于跨平台迁移。
- `presenterVideo: null` 显示人物占位；`voiceTrack: null` 不输出旁白。
- 模板人物视频始终静音，声音只从 `voiceTrack` 输出，避免双人声。仅放入人物视频不会自动有声音。
- 人物和声音应来自同一最终时间轴且足够长；模板不会自动修正嘴型或拉伸时长。
- `referenceImage` 在多个位置复用。现有裁切按 2992 × 1060 双人画布设计，换成不同构图要同步修改相关裁切与镜头，不能只换路径。
- 若本期没有访谈图，应重新设计相应场景与配置使用，不要把中性占位继续当作真实证据。

若粗剪后的 `presenter-final.mp4` 已有正确人声，可以提取成独立轨道。**确认输入确实是最终剪后版本**，在新工程中执行：

```powershell
ffmpeg -n -i "public/media/presenter-final.mp4" -vn -c:a pcm_s16le "public/media/voice-final.wav"
```

`-n` 遇到已有目标文件会拒绝覆盖。该命令只提取音轨，不会去噪、删停顿或完成字幕对齐；有 BGM 的混合音轨也不会因此自动分离成人声。

## 6. 重做字幕、事件与总时长

正式项目需要同时改以下内容：

| 文件或数据 | 应改什么 |
| --- | --- |
| `src/Root.tsx` | 本期宽高、fps、`durationInFrames` |
| `src/captions.json` | 本期真实字幕、稳定 `id`、实测开始／结束时间 |
| `timeline.json` | 字幕对应动作、物体身份、镜头与声音落点，作为可检查的制作记录 |
| `src/FilmV3.tsx` | 场景分界、镜头、人物裁切、转场与字幕层 |
| `src/CareerActionV3.tsx`、`src/ComicThreadV3.tsx` 等 | 按本期语义修改动作与道具，不机械保留旧案例关系 |

总帧数依据最终声音时长与选定 fps 计算，并在整帧边界校准结尾。例如 50 fps 的一帧为 0.02 秒。检查最后一个音节、字幕与视觉收束是否都在输出范围内，不能沿用默认的 537 帧截断长稿。

时间轴最小示例：

```json
{
  "fps": 50,
  "duration": 4.0,
  "timingSource": "DEMO / 手写示例，未对齐真实音频",
  "captions": [
    {"id": "cue-select", "start": 1.0, "end": 3.0, "text": "选中最重要的一句。"}
  ],
  "events": [
    {
      "id": "page-select",
      "cueId": "cue-select",
      "objectId": "working-page",
      "action": "同一张纸上的目标句逐渐被选中",
      "phase": "land",
      "offset": 0.0,
      "duration": 0.6
    }
  ]
}
```

动作时间为 `caption.start + event.offset`，示例中为 1.0 秒，持续 0.6 秒。稳定的 `cueId` 指向已有字幕 `id`；`objectId` 表明画面中连续存在的对象，不能只用同名 ID 掩盖物体实际被换掉。

`prepare` 可提前准备，负 `offset` 必须解释 `anticipationReason`；`land` 是语义落点；`exit` 是退场或收束。所有绝对时点必须在片长内，同轨字幕不能重叠。详见[格式规范](../references/timing-format.md)。

在工程目录执行检查，将 `<Skill目录>` 换成实际安装目录或下载仓库目录：

```powershell
python -X utf8 "<Skill目录>/scripts/check_timeline.py" "timeline.json" --csv "alignment.csv"
```

`alignment.csv` 默认拒绝覆盖；第二次导出可换新文件名。检查器只验证数据结构、引用和时间范围；**它不会把 `timeline.json` 自动导入 V3 源码，也不会改变 Remotion 场景**。需要由 Agent 按已校准的时间轴实现画面与字幕，避免记录数据和渲染源码各自漂移。

## 7. 处理声音与字幕安全区

保留一份声音母带作为合成基准。BGM 与音效应服从人声清晰度和语义落点，不为踩节拍随意加速口播。默认示例没有音乐或动作音，历史案例提到的 BPM 与音效数量也不是必须复刻的标准。

字幕应准确、读得完且不遮关键内容。检查：

- 深浅背景切换的中间帧，是否出现浅底白字或深底黑字。
- 长句换行、数字与专有名词，是否被人物、手势、证据或边界遮住。
- 目标播放器／平台交互区域，是否会盖住底部字幕；模板坐标不是通用平台安全保证。
- 人物转为小窗时，脸、嘴与重要手势是否仍清楚。

只有使用者明确要求换声、生成头像或数字人时，才讨论相应服务、授权和费用。当前 Skill 不附带私人声音或默认人物。

## 8. 预览、导出、检查

在新工程目录运行：

```powershell
npm run check
npm run dev
```

预览时先看开头、每个关键词落点、转场的前／中／后状态及结尾；根据画面修改后再导出：

```powershell
npm run render
```

V3 默认脚本导出 `out/presenter-v3-example.mp4`。新一期可以在本期工程中改输出名称，但交付说明必须与真实文件一致。

检查媒体信息和完整视频解码的示例：

```powershell
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate -of json "out/presenter-v3-example.mp4"
ffmpeg -v error -i "out/presenter-v3-example.mp4" -f null -
```

终端无解码错误只说明媒体能解码，不能证明台词正确、音画同步或视觉好看。抽听真实音轨与所有修改切口，若未完整听看，应写明抽查范围。

建议检查记录分开写：

| 结论 | 支撑它的实际证据 |
| --- | --- |
| 源码／时间结构通过 | TypeScript、时间轴检查的实际返回结果 |
| 导出完成且可解码 | 输出文件、媒体参数、完整解码结果 |
| 视觉抽查完成 | 检查过的具体时间点与发现／修复 |
| 完整音画复核完成 | 确实从头到尾听看后的记录 |
| 本期风格被认可 | 使用者对本期版本的实际反馈 |

不要把一个结论代替另一个。Skill 或模板的历史检查也不能作为本期成片检查记录。

## 9. 交付与下一期复用

建议每期交付：

- 实际导出的视频与便于查看的预览。
- 可编辑工程源码、`package.json`、`package-lock.json` 与必要的合法媒体。
- 本期字幕、语义时间轴和 `TIMELINE.md`。
- `SOURCES.md`：素材来源、用途、采集或生成方式及需要保留的许可说明。
- 真人粗剪的工程与源片到剪后时间映射；数字人注明默认跳过该步骤。
- 实际运行命令和检查范围，注明仍未验证的项目。

分享工程前排除账号配置、密钥、私人人像／声音及不应公开的原始素材。若媒体不能随包分发，保留明确的替换说明与预期文件接口，不要交付失效的私人绝对路径。

下一期从独立的新工程开始，复用视觉系统与组件，重新建立本期主题、最终声音与动作时点。发布、付费生成或账号绑定应依据使用者的明确指令另行处理。
