# v3.0.0-rc.2：从完整镜头复用转向 UI 设计语言

本次纠偏：用户要的是换主题仍有同一类 UI 设计、层次、交互与运动气质，并不要求重复原片剪辑。之前六个完整场景限制了自由布局，容易只替换内容。本次将设计规则提升为入口，并实际增加组合能力。

## 改了什么

- 新增 `ui-stage`：10 类 UI 节点，自由坐标、稳定 ID、逐属性关键帧和独立焦点相机；没有内置场景步骤。
- 文字、选中态、图片、按钮与计数可以按本期语义改变；图片含状态切换资源均校验、复制、等待加载。
- 校验器支持自定义语义落点，正式项目继续关联实测字幕。仍使用相对媒体路径和独立工程。
- 新主入口先设计信息结构、内容层级、状态与镜头。旧完整场景仅在适合本期内容时复用。
- 默认工程改为资料工作台，另有行程时间轴例子。两者用相同节点系统编排不同布局和动作。

## 可迁移能力和未验证内容

资料例子采用列表与详情；行程例子采用交通比较与日程重排。两者不是六场景替换数据，渲染器根据各自节点与时间线绘制。可在无需改 React 的前提下重新排列这些节点，改变内容、状态与镜头。

这不等于任意题材、任意模型都能自动达到用户要的风格。新组合机制尚未做低能力模型盲测；历史六场景的轻模型试用不能算本次验证。复杂视频贴图、3D与未知控件仍需扩展。两个样例是无声示意设计，**用户风格认可状态为 pending**。
