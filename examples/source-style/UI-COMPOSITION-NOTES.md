# 行程 UI 组合示例

本例是 15 秒、1080 × 1920 的无声开头演示。使用 `ui-stage` 自由组合界面节点，不依赖六个既有镜头机制。它与资料阅读示例采用不同的信息组织：旅行目的地 → 交通方式 → 单列时间轴 → 行程保存。

## 信息结构

- 顶部是应用名称、保存状态、目的地与出发日期。小幅目的地插画使用仓库原创 `illustrations/journey-3.svg`，并不代表真实目的地照片。
- 交通区把两种可选方案并列，时间是核心信息，选择状态以边框、底色和标签一起表达。
- 行程区采用左侧时间、纵向连接线、右侧安排的窄屏日程结构。主信息为 15–28 字号，辅助信息为 11–12 字号。
- 底部持续展示这次选择的含义与保存按钮。字幕另占底部区域。
- 地点与班次均为示例数据，不接入实时交通服务。

## 状态与局部秒数

| 时间 | 操作和可见结果 |
| --- | --- |
| 0–3.2 秒 | 先看全局，再将视线带到两种交通选择，原先选中大巴。 |
| 3.43 秒 | 光标选择高铁；选中边框、班次标签和页顶状态共同改变。 |
| 5.18 秒 | 到达时间从 11:55 改为 10:18，提前 1 小时 37 分钟。 |
| 5.3–6.85 秒 | 原有日程节点保留 ID 并重新安排位置与时间；空出的区域加入 10:45 咖啡安排，数量从 4 增至 5。 |
| 6.85–10.4 秒 | 镜头停留看清新日程，再回到整体界面。 |
| 10.75–11.7 秒 | 点击保存，按钮先显示保存中，再与页顶一起显示已保存。 |
| 11.7–15 秒 | 保留最后状态供阅读，不继续无意义地移动。 |

数值轨迹先写停留关键帧，再写改变后的关键帧，避免对象从第 0 秒开始缓慢滑动。文字、颜色和状态在语义节点离散切换；镜头与界面状态使用各自的轨迹。界面布局、状态顺序和内容均来自本期表达，不要求其他选题沿用旅行路线。

此文件仅记录本例的布局与意图。结构校验不等于视觉风格已获用户认可；渲染后的实际可读性与风格需另外查看。
