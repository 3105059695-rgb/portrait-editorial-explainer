# 轻量模型试读记录：整理读书摘录

## 设计

- 目标：用 15 秒、1080×1920 的无声机制样段，演绎给定口播“摘录越积越多，先把零散的记录收拢。每处理一条，就留下一条清楚的索引。整理好之后，再同步到自己的资料库。”
- 时钟与来源：没有提供音频，因此 `timing: demo`、`source.type: demo`；字幕分段与动作落点是按文案估计的演示时间，不代表测得的人声时点或真实剪辑映射。
- 语义链：4 张不同摘录卡连线汇成索引页 → 短摘录票据进入整理器，到达时累计示意条数 → 6 张整理卡逐张进入个人资料库，抵达驱动进度。
- 画面只使用机制组件的原生可编辑图形，无外部媒体。动作、标签、色值、场景名和局部时长均为本题新编；仅使用三种有对应语义的机制，没有照搬旅行案例的主题或拼齐六种效果。
- 场景重叠按契约设置：首镜 0–5.30 秒；第二镜 5.00 秒开始，以 0.30 秒 window 重叠；第三镜 10.00 秒开始，以 0.35 秒 circle 重叠。两次交接都有对象运动承接，样段连续覆盖到 15 秒。

## 实际验证

在 Skill 根目录运行：

```powershell
python -X utf8 scripts/source_episode.py validate examples/source-style/model-trial-reading.json
```

首次实际结果：退出码 0；输出 `valid: true`、`assets: 0`、`styleApproval: pending`、`mode: draft`。随后主 Agent 人工指出语义不一致：组件默认按 84 张票据比例累计，`value: 6` 不足以保证六个可见输入分别对应一条索引，因此“一条对应一条”的说明不能成立。

主 Agent 扩展了 `metric.events` 接口（整数 2–160；当 `events` 与 `value` 相同时逐事件计数）。本 JSON 随后设置 `events: 6`，使六个票据事件逐条对应六条示意索引，并再次运行同一命令。第二次实际结果：退出码 0；输出 `valid: true`、`assets: 0`、`styleApproval: pending`、`mode: draft`。未运行 production 校验、build、类型检查或 render。

## 状态边界

样片尚未构建或渲染，也没有进行连续画面审看；字幕和关键动作是否贴合实际口播尚未核对。这里记录契约校验通过及人工发现、接口扩展后的语义修正，不声称独立完成了无辅助的导演判断，也不声称渲染成功、审美等价或风格获批。取得实际配音后，应重新测量字幕与动作时点，再渲染并审看开头样段；`styleApproval` 保持 pending。
